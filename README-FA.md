# اپلیکیشن کارواش‌دار ماشینو (Flutter)

پنل موبایل اختصاصی **سمت کارواش‌دار** — با همان تم و فونت سایت ماشینو، به‌سبک اپ‌های رایاننده (مثل اسنپ راننده) و کاملاً متصل به بک‌اند.

- فونت: **ایران‌یکان (IRANYekan) فارسی‌شمار** — ارقام فارسی خودکار در همه‌جا
- سرور: پیش‌فرض **api.mashinow.ir** + تشخیص خودکار HTTPS/HTTP
- تم: رنگ اصلی **#00C290** + پالت روشن/تیره کامل (تم شب از تب «بیشتر»)، کارت‌های گرد بدون خط دور، سایه‌های نرم
- چیدمان: تمام صفحات ورود/ثبت **وسط‌چین با بخش‌بندی مشخص** (هویت / فرم / دکمه پایین) — هیچ صفحه‌ای محتوایش بالای صفحه چسبیده و پایینش خالی نیست
- راست‌به‌چپ کامل (RTL)

## راه‌اندازی (روی سیستم خودتان)

پیش‌نیاز: Flutter نصب باشد (همان نسخه‌ای که با اپ کاربر بیلد می‌کردید کافی است؛ میرورهای Myket هم فعال است).

**۱)** یک پروژه خالی با همین نام پکیج بسازید:

```powershell
flutter create --org ir.mashinow --project-name mashinow_carwash mashinow_carwash
```

**۲)** محتوای `lib/` این بسته را داخل `mashinow_carwash/lib/` کپی کنید (جایگزین فایل پیش‌فرض `main.dart`)، فایل `pubspec.yaml` و پوشه `assets/` را هم رونوشت کنید.

**۳)** تنظیمات اندروید (خیلی مهم — بدون این دو مورد اپ به سرور وصل نمی‌شود):

فایل `android/app/src/main/AndroidManifest.xml` را باز کنید و تگ `<manifest>` و `<application>` را این‌شکلی کنید:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET" />
    <application
        android:label="کارواش ماشینو"
        android:name="${applicationName}"
        android:icon="@mipmap/launcher_icon"
        android:usesCleartextTraffic="true"
        ...بقیه تنظیمات دست‌نخورده بماند...>
```

- `INTERNET` برای نسخه release لازم است.
- `usesCleartextTraffic="true"` برای وقتی است که اپ به مسیر `http://` برگردد (بدون آن اندروید ۹+ درخواست‌های HTTP را بلاک می‌کند). بعد از فعال‌شدن HTTPS مطمئن روی سرور، می‌توانید این خط را حذف کنید.

**۴)** اجرا:

```powershell
flutter pub get
flutter run
```

## اتصال به بک‌اند

پیش‌فرض به سرور اصلی وصل است: `https://api.mashinow.ir/api` — همان بک‌اند Django که همه داده‌ها (نوع خودروها، کارواش‌ها، رزروها، کیف پول) روی آن است.

### تشخیص خودکار HTTPS/HTTP (جدید)

اگر سرور هنوز گواهی SSL نداشته باشد و HTTPS جواب ندهد، اپ **خودش** یک‌بار با `http://api.mashinow.ir` امتحان می‌کند، اگر جواب گرفت همان را برای اجراهای بعدی یاد می‌گیرد (در SharedPreferences ذخیره می‌شود). یعنی بدون هیچ تنظیمی، هم HTTPS و هم HTTP کار می‌کند.

> ⚠️ برای اینکه مسیر HTTP هم روی اندروید ۹+ بلاک نشود، حتماً `android:usesCleartextTraffic="true"` را در AndroidManifest بگذارید (مرحله ۳ بالا).

اگر خواستید سرور دیگری را نشانی‌دهی کنید:

```powershell
flutter run --dart-define=MASHINOW_API_BASE_URL=http://82.115.21.39
```

## نکته مهم درباره کد تایید (مثل اپ کاربر)

روی بک‌اند فعلی **درگاه پیامکی تنظیم نشده**؛ سرور کد را داخل پاسخ «ارسال کد» برمی‌گرداند. این اپ همان کد را در یک چیپ آبی نمایش می‌دهد و باکس‌ها را خودکار پر می‌کند تا ورود کامل شود. به محض وصل‌شدن درگاه پیامک واقعی (کاوه‌نگار و…)، فیلد `code` از پاسخ سرور حذف می‌شود و این رفتار خودبه‌خود غیرفعال می‌شود — نیازی به تغییر اپ نیست.

## ساخت خروجی release (برای کافه‌بازار/مایکت)

```powershell
flutter build apk --release
```

خروجی: `build/app/outputs/flutter-apk/app-release.apk` (بدون keystore با کلید debug امضا می‌شود؛ برای انتشار عمومی keystore اختصاصی بسازید — راهنمای کاملش در README اپ کاربر هست).

## ساختار کد

```
lib/
├── main.dart / app.dart        # بوت‌استرپ + دروازه مسیر (ورود/ثبت/پنل)
├── core/
│   ├── api.dart                # Dio + توکن خودکار + تمدید 401 + باز کردن پاکت پاسخ
│   ├── session.dart            # نشست (توکن‌ها + مرحله ثبت) — ChangeNotifier
│   ├── models.dart             # مدل‌ها عین شکل واقعی پاسخ سرور
│   ├── jalali.dart             # تبدیل شمسی + فرمت تاریخ (الگوریتم استاندارد jalaali)
│   ├── format.dart             # ریال→تومان + جداکننده هزارگان
│   ├── theme.dart              # توکن‌های طراحی سایت
│   └── ui.dart                 # دکمه/فیلد/کارت/چیپ/... + قالب وسط‌چین صفحات
├── auth/login_page.dart        # ورود دو مرحله‌ای
├── onboarding/                 # ۴ مرحله ثبت‌نام + انتخابگر عکس
└── home/                       # پوسته + داشبورد + نوبت‌ها + مشتری حضوری + ...
```

بدون code-generation است (نیازی به build_runner ندارد) و فقط از ۴ پکیج عمومی استفاده می‌کند: `dio`, `shared_preferences`, `image_picker`, `url_launcher`.

## تغییرات نسخه v4 (تم شب + رفع ۶ مشکل گزارش‌شده)

| مورد | توضیح |
|---|---|
| **تم شب** | حالت شب کامل با پالت اختصاصی (زمینه سبز-تیره، متن روشن). پیش‌فرض «سیستم» است و از تب «بیشتر» با گزینه‌ی **تم اپ** بین سیستم / روشن / شب عوض می‌شود (انتخاب ذخیره می‌شود). |
| **رنگ اصلی جدید** | همه‌ی رنگ‌های تأکیدی (کاشی‌های آمار، چیپ‌ها، دکمه‌ها، آیکون‌ها) از خانواده‌ی رنگ اصلی **#00C290** شدند — رنگ‌های پراکنده (صورتی/زرد/بنفش) حذف شدند. قرمز فقط برای خطا/لغو ماند. |
| **کرش ذخیره‌ی زمان‌های کاری** | خطای `SessionScope not found in widget tree` رفع شد — SessionScope حالا بالای Navigator است و همه‌ی صفحات push شده (ویرایش زمان‌ها، کیف پول و...) به نشست دسترسی دارند. |
| **گیر کردن اپ در اجرای بعدی** | قبلاً اگر وضعیت پروفایل در بوت نرسید، اپ برای همیشه روی اسپلش می‌ماند. حالا صفحه‌ی خطا با دکمه‌ی **تلاش مجدد** و **خروج** نمایش داده می‌شود + بازیابی پروتکل HTTP/HTTPS قبل از اولین درخواست کامل می‌شود. |
| **نوار ناوبری شناور** | منوی پایین شناور شد: گوشه‌های نرم + **بلور شیشه‌ای** (BackdropFilter) + سایه؛ دکمه‌ی گرد «مشتری حضوری» به آن سمت چپ داک شده. |
| **متن زیر نوار وضعیت** | صفحات پنل داخل SafeArea قرار گرفتند + رنگ آیکون‌های نوار وضعیت با تم همگام می‌شود. |
| **آخرین نوبت‌ها در داشبورد** | باکس «نوبت‌های امروز» به **«آخرین نوبت‌ها»** تبدیل شد: نوبت‌های آنلاین + حضوری با هم (اول نزدیک‌ترین نوبت پیش‌رو، بعد نوبت‌های گذشته). بعد از ثبت مشتری حضوری، داشبورد بلافاصله رفرش می‌شود (و با برگشتن به اپ هم رفرش می‌شود). |
| **کد تایید مثل اپ اصلی** | همان اندپوینت پیامکی سایت/اپ صدا زده می‌شود؛ تا وقتی درگاه پیامک روی بک‌اند فعال نشده و سرور کد را در پاسخ برمی‌گرداند، باکس‌ها خودکار پر و ورود **خودکار** انجام می‌شود + چیپ «کد تایید شما» با توضیح. با فعال‌شدن پیامک واقعی (کاوه‌نگار و...) کد فقط پیامک می‌شود و این حالت خودبه‌خود خاموش می‌شود. |
| **دکمه‌های تمام‌عرض** | همه‌ی دکمه‌های اصلی (ادامه/تایید/ذخیره) تمام‌عرض شدند — نه وسط‌چین کوچک. |

> این نسخه روی همه‌ی فایل‌ها اثر گذاشته (تغییر رنگ‌ها به‌صورت سراسری + پشتیبانی دارک‌مود). کل بسته را جایگزین کنید، `flutter clean` بزنید و اجرا کنید.

## تغییرات نسخه v4.1 (رفع ۵ خطای کامپایل const)

| مورد | توضیح |
|---|---|
| **خطای Constant evaluation error** | ۵ مورد استفاده از `AppColors` (گتر تم شب) داخل عبارت‌های `const` باقی مانده بود و بیلد را می‌شکست: `ui.dart:177` (برچسب «اختیاری»)، `add_customer_page.dart:191` و `224` (تیترهای «انتخاب ساعت» و «خدمات»)، `onboarding/widgets.dart:59` (ستاره‌ی اجباری فرم‌ها) و `booking_card.dart:335` (متن «خدمتی ثبت نشده»). کلمه‌ی `const` از این ویجت‌ها حذف شد (خود ویجت‌ها دقیقاً همان‌طور رندر می‌شوند؛ فقط دیگر compile-time constant محاسبه نمی‌شوند). |
| **ابزار بررسی سخت‌گیرانه‌تر** | اسکنر داخلی بررسی «const + AppColors» دو اشکال داشت (const بعد از `if` بدون آکولاد و const بعد از کامنت فارسی را نمی‌دید + باگ stack در تطبیق پرانتز) که باعث شده بود این ۵ مورد در بررسی v4 پنهان بمانند. اسکنر اصلاح شد و حالا کل پروژه را دوباره تأیید می‌کند: صفر مورد باقی‌مانده. |

> اگر نسخه‌ی v4 را قبلاً باز کرده‌اید و فقط می‌خواهید بیلد درست شود، کافی است ۴ فایل `lib/core/ui.dart`، `lib/home/add_customer_page.dart`، `lib/onboarding/widgets.dart` و `lib/home/booking_card.dart` را از این بسته جایگزین کنید.

## تست سریع

1. با شماره‌ای که نقش کارواش دارد وارد شوید (شماره کارواش تست: `09120000000`) — کد تایید بعد از زدن «دریافت کد تایید» به‌صورت چیپ آبی نمایش داده می‌شود.
2. اگر ثبت‌نام کامل نباشد، اپ خودش شما را به مرحله بعدی ثبت می‌برد.
3. بعد از ورود: داشبورد آمار، لیست نوبت‌ها، ثبت مشتری حضوری و بقیه بخش‌ها فعال‌اند.
